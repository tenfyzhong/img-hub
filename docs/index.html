Cloudflare deployment

From repository to stable links.

Deploy a private, multi-user file and text hub with D1 and R2. No shared upload code and no external storage channel.

Deploy to Cloudflare View source

Choose a deployment path

Cloudflare button

Fastest start. The detected deploy command provisions D1, R2, and Turnstile before the final Worker deployment.

CLI one-command

Explicit provisioning, the initial D1 schema, Turnstile, the daily retention task, and Worker deployment.

GitHub Actions

Secret-free CI on develop and stable deployment on main, including D1/R2 initialization and the scheduled backend task.

Local development

Local D1 and R2 persistence through Wrangler, with no remote resources required.

One-click deployment

  1. Open the Cloudflare deployment screen.
  2. Authorize the requested account, keep the detected npm run deploy command, and deploy. It automatically provisions D1, R2, and a managed Turnstile widget.
  3. Open the generated workers.dev URL. The first request initializes the D1 schema.
  4. Set a password for the fixed administrator username admin. Retention defaults to 91 days and can be changed under Site settings.

If automatic resource provisioning is unavailable for your account, use the CLI flow. It discovers or creates named resources explicitly.

One-command CLI deployment

Install Node.js 22 or newer, then run:

git clone https://github.com/tenfyzhong/img-hub.git
cd img-hub
./deploy.sh

The script opens Wrangler login if needed, creates or reuses img-hub-db, img-hub-files, and a managed Turnstile widget, applies the initial D1 schema, stores the widget secret as a Worker Secret, and deploys the daily retention task.

Custom names or placement

IMG_HUB_DATABASE_NAME=my-hub-db \
IMG_HUB_BUCKET_NAME=my-hub-files \
IMG_HUB_D1_LOCATION=apac \
IMG_HUB_R2_LOCATION=apac \
IMG_HUB_TURNSTILE_DOMAINS=images.example.com \
IMG_HUB_WECHAT_VERIFY_FILENAME=30192898bf0120ae25f69bdce9e25e77.txt \
IMG_HUB_WECHAT_VERIFY_CONTENT=verification-content-from-wechat \
./deploy.sh

The operation is idempotent and never deletes a D1 database or R2 bucket. The generated workers.dev hostname is detected automatically; IMG_HUB_TURNSTILE_DOMAINS adds comma-separated custom hostnames. Provide both optional WeChat variables together to publish the exact verification content at the site root without changing the checked-in public/ directory.

Create the Cloudflare deployment token

For GitHub Actions, create a user API token under My Profile → API Tokens. Select Create Token, then choose Create Custom Token. This is the recommended least-privilege option because no built-in template exactly matches ImgHub. Do not use the legacy Global API Key.

The faster Edit Cloudflare Workers template is broader than ImgHub needs: it includes KV, Tail, and Zone route access while omitting D1 and Turnstile. If you start from that template, remove the unused permissions and add D1 and Turnstile. The custom-token permission set below is clearer and safer.

Add exactly these permissions

ScopePermissionAccessWhy ImgHub needs it
AccountAccount SettingsReadLet Wrangler identify and validate the selected account.
AccountWorkers ScriptsEditDeploy the Worker, static assets, bindings, schedules, and secrets.
AccountD1EditCreate or reuse D1 and apply the initial schema.
AccountWorkers R2 StorageEditCreate or reuse the R2 bucket and manage its deployment binding.
AccountTurnstileEditCreate, read, and update the managed login widget.
UserUser DetailsReadAllow Wrangler authentication checks.
UserMembershipsReadAllow Wrangler to resolve the user's account membership.

In compact permission notation, the rows are Account Settings Read, Workers Scripts Edit, D1 Edit, Workers R2 Storage Edit, Turnstile Edit, User Details Read, and Memberships Read. Some Cloudflare surfaces show write permissions as Write instead of Edit; for example, Turnstile Sites Write is the same required write capability.

Restrict the resource and store the secret once

  1. Under Account Resources, choose Include → Specific account → your deployment account. Do not select all accounts unless one repository intentionally manages all of them.
  2. The default workers.dev deployment needs no Zone permission. Add Zone → Workers Routes Edit only if you later configure a Worker route on a specific zone.
  3. Select Continue to summary, verify the seven rows and the one account, then select Create Token.
  4. Copy the secret directly into the GitHub Actions secret CLOUDFLARE_API_TOKEN. Add the selected account's ID separately as CLOUDFLARE_ACCOUNT_ID.

Cloudflare's current references are the authoritative source for token creation, built-in templates, and permission names. Re-check them if the dashboard wording changes.

GitHub Actions deployment

  1. Fork the repository for Sync fork updates, or use it as a Template repository for an independent history. The maintainer enables Settings → General → Template repository once.
  2. Follow the least-privilege token guide. Automatic challenge setup requires Turnstile write access.
  3. Add repository Action secrets CLOUDFLARE_API_TOKEN and CLOUDFLARE_ACCOUNT_ID.
  4. When WeChat supplies a verification file, add repository variables IMG_HUB_WECHAT_VERIFY_FILENAME and IMG_HUB_WECHAT_VERIFY_CONTENT under Settings → Secrets and variables → Actions → Variables.
  5. Run Deploy to Cloudflare manually or push to main.

Optional WeChat root verification file

Set both variables or neither. Use the issued root-level .txt filename, such as 30192898bf0120ae25f69bdce9e25e77.txt, and copy the issued content exactly. Safe names may contain letters, numbers, _, and -, but no directory, spaces, or other extension. A partial or unsafe configuration fails before any Cloudflare resource changes.

Deployment builds an isolated temporary copy of the static assets, writes the content without adding a newline, publishes it at a URL such as https://images.example.com/30192898bf0120ae25f69bdce9e25e77.txt, and removes the copy afterward. It does not modify or commit public/. The value is intentionally a Repository Variable because the verification content becomes public at that URL. Both deploy.yml and release.yml use the same repository-specific values, including in forks.

main is always stable and deployable; development enters through develop. Secret-free CI validates pull requests, while every main update runs stable verification. See the contribution guide for branch protection and release flow.

The deployment workflow works unchanged in the original repository and every fork. Each repository supplies its own secrets and therefore deploys only to its owner's Cloudflare account. Its default img-hub-{repository-id} prefix prevents Worker, D1, and R2 collisions; an IMG_HUB_RESOURCE_PREFIX repository variable overrides it.

The stable workflow tests and builds the project, initializes D1/R2/Turnstile, applies the initial D1 schema, and deploys the application with its scheduled retention task and Turnstile secret. It reports a skipped deployment instead of failing when Cloudflare secrets are absent. Fork owners enable Actions once, keep custom commits off main, then use Sync fork → Update branch. Template-created repositories do not have this sync relationship.

Destroy Cloudflare deployment

Danger — destructive and irreversible. Use this manual workflow only for a disposable test deployment. It permanently removes the named Worker, every R2 object and the bucket, D1, and the managed Turnstile widget. No backup is created.

On main, open Actions → DESTRUCTIVE: Destroy Cloudflare deployment. Enter the exact owner/repository, enter DESTROY owner/repository, and acknowledge permanent data loss. The workflow refuses any mismatch and uses the same repository-specific prefix as deployment. Bucket locks must be removed before R2 can be emptied. DNS, manually created routes, and resources outside the named deployment are not removed.

Publish this guide

In repository Settings → Pages, select GitHub Actions as the source. The Pages workflow publishes both languages from docs/.

API keys and Agent Skill

After changing a temporary password, open the dedicated, full-width API keys menu directly below Security and create a named key. The password surface is also full-width. Multiple keys expand downward on this separate page without affecting the password form. Copy the imh_... value immediately: only the hash is stored. Keys are revocable, may expire, and are limited to the owner's files and text.

Copy skills/img-hub into the AI agent's skills directory and configure its process:

export IMG_HUB_URL=https://images.example.com
export IMG_HUB_API_KEY=imh_your_key_shown_once

The included client lists, uploads, replaces, and deletes files, and publishes or replaces text. Never place IMG_HUB_API_KEY in prompts, logs, or source control.

Chrome, Edge, and Firefox extension

Each GitHub Release contains a generic Chromium ZIP for Chrome and Edge and a Firefox ZIP. No service domain is compiled into either package: configure the deployed URL in the popup, grant access to that origin, then sign in.

Unzip the Chromium package and use Developer mode → Load unpacked. For Firefox development, use about:debugging#/runtime/this-firefox and Load Temporary Add-on. The extension stores its deployment URL and login token locally, never the password, and supports upload, list, copy URL, replace, and delete.

npm install
npm run build:extension

GitHub Release and store publication

Set the numeric package.json version, merge the release to main, then push its matching tag such as v0.3.0. The release workflow rejects tags outside main, tests, builds the two generic packages, deploys to this repository's Cloudflare account when configured, and creates a GitHub Release.

Automatic store publication is enabled per complete secret set:

  • Chrome: CHROME_PUBLISHER_ID, CHROME_EXTENSION_ID, CHROME_CLIENT_ID, CHROME_CLIENT_SECRET, CHROME_REFRESH_TOKEN
  • Edge: EDGE_PRODUCT_ID, EDGE_CLIENT_ID, EDGE_API_KEY
  • Firefox: WEB_EXT_API_KEY, WEB_EXT_API_SECRET

Create each listing once in its developer portal. An incomplete set skips only that store.

First run and accounts

There is no default password. The fixed administrator username is admin; the first visitor chooses and confirms its password on the initial screen. Password fields support show/hide controls. Setup closes after that account exists.

  1. Create users in Administration and share temporary passwords securely.
  2. Users can sign in with a temporary password, but content operations remain blocked until they change it.
  3. An administrator reset revokes every session for that user and restores the password-change requirement.

Passwords are salted PBKDF2-SHA-256 hashes. A browser access session lasts 7 days and a rotating refresh session lasts 30 days. The web UI automatically uses the HttpOnly refresh cookie after access expiry and invalidates it while issuing a new pair; 30 days without a refresh requires password login. D1 stores only token hashes, while both cookies use SameSite=Strict and Secure over HTTPS.

Three failed logins for the same normalized username and Cloudflare client IP within 15 minutes require an on-demand Turnstile check. The Worker validates each single-use token for the login action and current hostname. D1 stores only a SHA-256 attempt identifier and counters; a successful login clears them.

Browser language

The first preferred browser locale selects the interface: a language beginning with zh uses Simplified Chinese and every other language uses English. The header's EN / 中文 control saves an explicit browser-local override.

Static controls, dynamic lists and messages, confirmations, dates, empty states, and common API errors are translated. Administrator-configured site appearance is shared between languages; built-in unsaved welcome copy has separate translations.

Forgotten administrator password

There is no email recovery or backdoor. A deployment owner resets the sole administrator with the included D1 tool. For local data, stop the server and run:

npm run admin:reset
npm run dev:local

For a deployment, authenticate Wrangler, find the exact database name in D1, and explicitly select the remote database:

npx wrangler login
npm run admin:reset -- --remote --database YOUR_D1_DATABASE_NAME

The hidden prompt creates a temporary password. Confirm administrators_reset is 1 and administrator_username is admin. The operation revokes administrator sessions and API keys, safely normalizes a legacy administrator name to admin, preserves the former name only as a public-URL alias, and requires a different password after login. A reset count of 0 means the wrong or an uninitialized database was selected.

GitHub Actions: Reset administrator password

  1. Under Settings → Secrets and variables → Actions, create or update IMG_HUB_ADMIN_RESET_PASSWORD with a new temporary password of 10–256 characters. The existing CLOUDFLARE_API_TOKEN must have D1 Edit access, and CLOUDFLARE_ACCOUNT_ID must still be configured.
  2. Open Actions → Reset administrator password → Run workflow, enter the exact deployed D1 database name, and select the confirmation checkbox.
  3. Confirm the log reports administrators_reset as 1. Sign in as admin, immediately choose a different permanent password, then delete the temporary repository Secret.

The workflow is manual-only and never accepts the password as an Actions input. It revokes all administrator sessions and API keys. Never put the temporary password in the database-name field, an input, issue, screenshot, or log.

Administration address, content audit, and disable account

There is no separate /admin URL. Open the site root, such as http://localhost:8787, sign in with username admin, and select Administration. A new database shows administrator password-and-confirmation setup at that same address. If local setup does not appear, persistent .wrangler/state/ already contains an account: use npm run admin:reset to preserve data or stop the server and use npm run local:reset to erase local test state.

Content audit and User management are separate administrator menus. Both lists use server-side search and pagination. User search fills the row and Create user opens a right-side drawer. Audit search covers file names, public IDs, uploaders, directories, and kinds. Blocking permanently deletes the R2 source object, returns 404 for the public link even after a cache hit, hides it from its owner, and retains the audit tombstone.

Disable account revokes the user's sessions and API keys, rejects login, and makes all resources owned by that account unavailable. Re-enabling permits a fresh login without restoring old credentials. The administrator cannot be disabled.

R2 retention

Administrators choose 1–3650 days under Site settings; D1 stores the value and supplies the 91-day default. The deployed Worker's daily scheduled task lists only users/ through its R2 binding and deletes expired objects.

Deployment removes only the obsolete fixed img-hub-default-expiration rule from earlier development builds; unrelated bucket lifecycle rules remain untouched.

The website never asks for a Cloudflare Account ID, bucket name, or API token and does not keep a runtime management token. Back up D1 and R2 before reducing retention because deletion is irreversible.

Isolation, paths, and replacement

users/{user-id}/file/trips/lake-20260806T040506123.png
/pub/7b62f18c6d304476a5edc8a4de176cb1?v=1

users/{user-id}/text/notes/hello-20260806T040506123.md
/pub/91ac1f75e0c84353bb9eca92c4f828a0?v=1

Each user ID owns separate internal file and text roots, while files and text share one /pub/{32-character-opaque-id} public route. The ID has no pub_ prefix. Resource kinds, usernames, directories, and names are not exposed. Former root, /file/, /text/, prefixed IDs, and username-based public paths are unsupported. Replacement retains the object key and random public path, increments D1's version, and returns a new ?v= value.

The Upload & publish entry provides equal-height tabs for file upload, text publishing, and remote-file import, with the import tab last. New file and text names receive a millisecond UTC timestamp; a blank text name is generated from its format, and text results provide the same URL/Markdown/HTML copy actions as files. Before direct upload, the browser calculates MD5 in chunks; a same-user, same-size match is copied to an independent R2 object without sending the file again. Remote import accepts images, documents, archives, audio, video, text, and other HTTP(S) files while retaining private-network and size checks. The enlarged drop zone opens the picker when clicked and accepts dragged files, pasted files, and clipboard images; uploads start immediately with progress. Remote imports stream real fetched-byte progress, use an indeterminate bar when the source omits its length, and then report the storage-saving stage. The separate Manage entry mixes files and texts in one resource list and root directory tree, with directory filtering, grid/list views, URL/Markdown/HTML copy, replacement, and deletion. The publishing UI supports Markdown and restricted rich text with equal-sized editor frames. Manager cards preview text, while oversized or unusually tall images remain contained inside the card. A durable timeline records uploads, imports, replacements, and deletions.

Cached file and text reads

GET requests with the current version, such as /pub/7b62…?v=3, use caches.default. A small D1 availability check runs first so moderation and disabled accounts override old cache entries; an allowed hit then skips the large R2 object read. Invalid, missing, deleted, blocked, and expired resources receive the localized ImgHub 404 page without revealing which case occurred.

The response header is X-ImgHub-Cache: MISS when content is stored, HIT when served from cache, and BYPASS for an unversioned URL, incorrect version, extra query parameters, or HEAD. Current positive numeric versions receive one-year shared-cache retention, while browser max-age=0 preserves the moderation check. Cache API entries are local to each Cloudflare data center.

Administrator site appearance

Open the separate Site settings administrator menu to configure the site title, tagline, welcome title, and welcome description. Values are kept in D1, have explicit length limits, and are rendered as plain text. Installations without saved values use the built-in defaults.

Local development

npm install
npm run dev:local

Open http://localhost:8787. A fresh state starts by setting the password for administrator admin; after that, use the real browser UI to test accounts, uploads, text, replacement, public links, deletion, API keys, and site appearance. Fail three logins for a test username and confirm Turnstile appears. Press Ctrl+C to stop.

The command explicitly uses wrangler dev --local. D1, R2, assets, and cache stay local, need no Cloudflare credentials, and persist under the ignored .wrangler/state/ directory. Local challenges use Cloudflare's public always-pass test keys; only an explicitly triggered challenge reaches the public Siteverify endpoint.

Start again from an empty local installation

npm run local:reset
npm run dev:local

Stop the server before resetting. The reset removes only this checkout's local D1, R2, and cache state; it cannot touch deployed Cloudflare resources.

Automated local checks

npm test
npm run test:local

The unit suite uses in-memory doubles. test:local also starts the complete Worker in an isolated non-persistent Wrangler runtime. Validate the production bundle without publishing with npx wrangler deploy --dry-run.

Troubleshooting

The Action cannot create resources

Check both secrets, the selected Cloudflare account, and token permissions for Worker scripts, D1, and R2.

Retention has not run yet

The scheduled backend runs daily at 03:00 UTC. Confirm the Worker has the checked-in cron trigger and the expected local or deployed R2 binding.

An expired URL returns 404 but remains listed

The retention task removes the object independently of D1. The owner can delete the stale row from the library.

A replacement still shows old content

Copy the newly returned URL. Its path is unchanged, but the ?v= value must match the latest version.
